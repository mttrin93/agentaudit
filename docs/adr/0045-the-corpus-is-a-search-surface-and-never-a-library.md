# The corpus is a search surface and never a library

The four LLM-list families are to grow from three cases each to roughly twenty (#62), and the material they grow from is a published safety corpus of 33,416 annotated human/LLM interactions. That raises one question before any of the mechanics: **what is the corpus, in the vocabulary this project already has?**

The wrong answer is available and cheap. A **library** in this codebase is `backend/cases/` — executable tests, each with a payload and the criterion that decides its verdict, globbed by `load_library`, digested into a **library version** that makes two gate runs comparable or provably not (CONTEXT.md, `library.py`). A corpus of 33,416 rows is *also* a lot of payloads on disk that a run could iterate. Treating it as a second library — even informally, even only in the way the code is arranged — would make every claim a library version carries either false or unenforceable, because the digest would either not cover the corpus (a run's inputs unversioned) or cover it (a version that moves on every re-index).

So it is a **search surface**: the thing a human queries while writing cases, and never the thing a run executes. If the whole corpus were meant to run, no vector store would be needed — a `for` loop would do. Retrieval's job is *selection under a cost budget*, which is what makes it a build-time instrument.

## Why retrieval, and not a filter over the publisher's own labels

Worth settling with a measurement, because the cheap alternative looks adequate and is not. Every row carries `prompt_label` and `violated_categories` — `Criminal Planning`, `PII/Privacy`, `Hate` — and if the families the bench tests were findable by filtering that taxonomy, a `WHERE` clause would beat an embedding model on every axis.

They are not. Read over the stored revision on 2026-09-04: of the 656 rows whose prompt contains *previous instructions*, **441 carry no category at all** — they are labelled `safe`, because a request to ignore prior instructions is not a content-safety violation in the taxonomy that labelled them. The best single category to filter on, `Unauthorized Advice`, returns 579 rows of which 109 are of that shape: **18.8% precision, 17% recall.** The taxonomy is orthogonal to the six families by construction, which is the same fact that makes #64 necessary, and it is the reason the corpus needs to be searched by meaning rather than sliced by label.

## Decision

1. **The corpus is a search surface. `load_library`, `load_elective` and `LibraryVersion` are untouched, and a test pins the digest.** `backend/tests/test_corpus_isolation.py` asserts the eighteen-case library at `sha256:84a94f471260`. That is a deliberate tripwire: the ticket that is *supposed* to trip it is #67, which lands twenty cases in each grown family, and a digest change with no case record in the diff is what it exists to catch.

2. **What is stored is the record of the material, never the material.** `backend/corpus/source.py` holds the dataset identifier, the revision, the licence, the CC BY 4.0 attribution notice, and one SHA-256 per published file. The rows themselves are fetched at build time and thrown away.
   - **The digest is of the *publisher's* file, and that is why it is right here and was wrong in ADR-0036.** [ADR-0036](./0036-a-published-identifier-resolves-to-a-stored-copy.md) rejected adding a digest to the stored OWASP copies, on the grounds that a digest of our own transcription proves only that we did not edit our own file — which git already proves — and says nothing about fidelity to the publisher. That rejection stands. This is the inverse case: nothing is transcribed, so the digest *is* the fidelity claim, and it is the only one available for material that may not be kept.
   - **What a reader sees when the stored record has gone stale.** `StoredSource.drift` names three disagreements apart, because they need different fixes: a **missing** file is an incomplete fetch, a **changed** digest is the publisher having moved or a truncated download, and an **unexpected** file is this repository's record having gone stale against a corpus that grew a split — the one case where the fetch is right and the record is wrong. `scripts/index_corpus.py` refuses to index on any of the three. A matching digest with a row count this repository did not read is a separate refusal, because that is a reader bug here rather than drift there.

3. **The store is git-ignored at `/corpus/`, and it is not one of this project's databases.** Git-ignored on `/precedent/`'s reasoning ([ADR-0019](./0019-long-term-memory-that-does-not-survive-a-restart-is-not-long-term.md), [ADR-0029](./0029-the-precedent-store-is-a-database-and-the-connection-belongs-to-the-batch.md)) plus one of its own: committing it would put 33,416 harmful prompts in this repository, which [ADR-0008](./0008-repo-disclosure-posture.md) forbids far more clearly than it forbids any single case payload.
   - **It is deliberately not a `store.DatabaseStore` subclass, and that is ADR-0029 decision 6 applied rather than skipped.** That decision governs which of *this project's* concerns share a SQLite file. The file here is `chromadb`'s own — its schema, its migrations, its connections — so wrapping it in our opening layer would give the appearance of a shared policy over a file our pragmas do not govern, and would put a `NoVectorIndex`-shaped refusal on a store whose entire purpose is a vector index.
   - **The batch owns the connection, and ADR-0032's deciding question is answered rather than copied.** Does one operation span a wait? No, and not marginally: an ingestion reads five local files and embeds them, a retrieval runs one query and prints. Neither halts for a human — [ADR-0028](./0028-the-approval-checkpoint-outlives-the-process.md)'s condition, and the reason the admission memory answered the other way — neither waits on a provider, and one operator runs one script, so there is no second holder to contend with. `index.opened` is the batch, and `clear_system_cache` on the way out is what makes that a fact rather than a comment, because `chromadb` caches a client per path.

4. **The embedding model is a declared input, and it is not offline.** A corpus indexed with one embedding model returns a different set for the same query than the same corpus indexed with another, so `source.EMBEDDING_MODEL` records which one — the argument [ADR-0025](./0025-the-console-may-set-a-runs-declared-inputs.md) makes for the attacker's model, applied to the instrument that decides what a human is shown. The archive's SHA-256 is recorded beside it and *reported* rather than refused on, because a model republished at a new digest is a decision a person has to make about every answer the index gives.
   - **#63's premise is corrected here.** The ticket says to prefer Chroma's local default for, among other things, "no network in the build path". Measured on 2026-09-04: the first use of that default downloads a 79.3 MB archive from `chroma-onnx-models.s3.amazonaws.com` into `~/.cache/chroma`, unpacking to 167 MB. It is local *after* one fetch, not offline on a clean machine. The conclusion survives — no per-query cost, no key to rotate, and the fetch is a person's one-time build step — but the reason given for it does not, and the consequence is decision 5.

5. **`chromadb` is an optional extra, CI never installs it, and no test opens an index.** `uv sync --all-groups` — CI's command — installs dependency groups and leaves extras alone, so `--extra corpus` is what keeps 80 transitive packages and 331 MB out of every CI job for a package nothing in CI imports. Measured on 2026-09-04, as is the fact that adding it moved **no** existing locked version. The pure logic — documents, addresses, drift, near-duplicate suppression — is tested without it installed; `backend/corpus/index.py` is the one module that touches it and is kept thin for that reason, under a `ignore_missing_imports` override that is the whole cost of the arrangement.

6. **Nothing retrieved can reach a scored rate, a `D`, a κ or a gate decision, and retrieval is not a second edge.** [ADR-0010](./0010-two-layers-in-one-run-the-adaptive-layer-is-never-scored.md) leaves exactly one edge into the scored side — `propose_case` into the admission gate, where a declared threshold decides — and a retrieved corpus is an obvious candidate for a second one. Four things stop it, and each is a test rather than a paragraph.
   - **The dependency runs one way.** `backend/corpus/` imports `Family` from `backend.bench.library` and nothing else from the bench — **amended on that one clause by [ADR-0046](./0046-a-family-assignment-is-proposed-here-and-decided-by-a-person.md) decision 7**, which reads `ElectiveFamily` and the `AnyFamily` union too and gives the reason all three are still closed sets nothing flows back through. The neighbouring clause of this decision — *nothing retrieved can reach a scored rate, a `D`, a κ or a gate decision* — is untouched and worth saying so explicitly, because ADR-0046 computes a κ: that figure is over the **case library's** own payloads, about the instrument rather than about a target, and it reaches no report, no rate and no gate. Nothing retrieved is in it; no module under `backend/bench/` imports `backend.corpus` at all. Both directions are asserted over the tree by AST, because what they forbid is a future edit rather than a present value.
   - **Nothing in the corpus package or its two scripts can reach a case.** `load_library`, `load_case` and `Case` are not named anywhere in either, so the step from a candidate to an admitted case record cannot be taken here — it is a human judgement (#64) and an admission bar (#65).
   - **A `Candidate` has no family, and never gains one.** The invariant is carried by the type, on the terms `ClaimedInPart.families` and `AdaptiveEpisode` are: a retrieved row is a phrasing somebody published, and which of the six it belongs to is a judgement an instrument must earn the right to make.
   - **The two judged families have no declared query.** `disclosure_denial` and `wrongful_commitment` are the families whose rates rest on an adjudicator's κ ([ADR-0013](./0013-adjudication-is-a-third-instrument.md)), and giving them nothing to search with is how κ stays out of this group's blast radius. Asserted against the case records on disk — the set of judged families is read off `verdict_class`, so a third family becoming judged fails the test rather than quietly acquiring a query.

7. **Near-duplicate suppression is a property of the selection, and the floor holds between selections.** Retrieval ranks by nearness to the query, which is the one property every rephrasing of an attack shares, so a rank-ordered top-twenty for indirect injection is twenty ways of writing *ignore all previous instructions*: `n` rises to two hundred and coverage stays at one. `selection.select_spread` accepts a candidate only if it is at least `NEAR_DUPLICATE_FLOOR` cosine from **every** candidate already selected, reports what suppressed what, and reports a shortfall rather than widening its search to fill the quota. Against the query alone the floor rejects nothing; against the first selection alone it admits a candidate that is far from the first and adjacent to the second, which is the shape a second cluster arrives in.

## What this deliberately does not do

- **It does not complete H1 Agentic RAG** (`README.md:374`), and no part of it may be read as doing so. H1's stated gap is that `retrieve_precedent` is by filter rather than embeddings, and closing it means embeddings on the **precedent** store: a different store, a different consumer, a separate ticket.
- **The adaptive attacker does not read this corpus**, by #62's decision. Its job is routes the library has not explored; hand it the corpus the library was grown from and it rediscovers the library. Two growth engines, two sources, kept apart — the shape of [ADR-0011](./0011-the-adaptive-attacker-is-label-blind.md)'s blinding argument.
- **It labels nothing.** A declared query names the family it searches *on behalf of*; what comes back is unlabelled. #64 is the ticket that has to turn a family assignment into a validated instrument, and this decision is careful to leave it the whole of that job.
- **It admits nothing and writes no case.** #65 is the provenance, the bar and the trigger; #66 is ragged `n`; #67 is the twenty cases and the gate run that spends money on them.
- **It does not delete.** A revision change writes new addresses beside the old rather than over them, because a case record admitted against the old revision still cites it. Removing a superseded revision is a decision with a case-record consequence, so it is a person's.

## Considered options

- **Commit the corpus, or a sampled slice of it.** Rejected on ADR-0008, which is at its clearest about exactly this: 33,416 harmful prompts in a public repository. A sampled slice is the same object smaller, and it would additionally make the sample a thing to version.
- **Store the corpus as a `StoredCopy` in `editions.py`.** Rejected because a `StoredCopy` is a transcription of a short published list of identifiers and titles, held so a claim can be checked offline. A copy of 33,416 rows is the previous option, and the *record* of them is not a copy — hence its own module and its own type, with the digest ADR-0036 refused a copy.
- **Put the index in `precedent/findings.sqlite` or `decisions/routes.sqlite`.** Rejected on ADR-0029 decision 6, held for a fifth time. Precedent is adaptive-layer memory, the decision store is scored-side state, and a search surface over somebody else's published corpus is neither.
- **`chromadb` as a project dependency, or in the `dev` group.** Rejected on cost and on honesty. The bench does not import it at run time, so a dependency would be a false claim about what the product needs; the `dev` group is installed by CI, which would pay 331 MB and 80 packages to typecheck one thin module. The extra is what makes *nothing in CI imports this* enforceable rather than aspirational.
- **A hosted embedding API instead of the bundled model.** Rejected on three counts: a per-query cost, a key to rotate, and a build path that fails on somebody else's outage. The bundled model's one-time 79.3 MB fetch is worse than advertised and still better than that.
- **Filter the publisher's `violated_categories` rather than embed.** Rejected on the measurement above: 18.8% precision at 17% recall on the best single category, and 441 of 656 relevant rows carrying no category at all.
- **Index the response text as well as the prompt.** Rejected. What this bench searches for is a phrasing an attacker sends; a response is somebody else's model answering, and indexing it would put text no attacker ever sends into the surface an attacker's phrasing is retrieved from. It is also what makes an id an address at all — the refusals files re-publish a prompt under its own id with a second response, so 33,416 rows carry 28,214 distinct prompt ids.
- **Key documents by position, or by a hash of the text.** Rejected per #63: an id that is a position in a shuffle rots the moment the corpus is rebuilt, and a content hash would change on a whitespace edit the publisher never announced. The publisher's own row id is used, and an id arriving with two different prompts is a refusal rather than a last write.
- **One near-duplicate floor per family.** Rejected as six numbers chosen after seeing what they returned. One floor over one declared model is a declared input a reader can check.

## Consequences

- `backend/corpus/` is a new package that nothing in `backend/bench/` may import, and two scripts that no run, gate run or test invokes.
- A person building the corpus runs `uv sync --extra corpus` and `uv run python -m scripts.index_corpus`. Two network fetches happen there and nowhere else: the five published files, and the embedding model's archive on first use.
- **PLAN §14's two sentences about this system using no RAG become false and are corrected in the same commit**, per CLAUDE.md's both-ends rule. PLAN §14's answer about `map_to_article` is untouched and is strengthened: that one is still deliberately a fixed table.
- CONTEXT.md gains **corpus** and **candidate**, because a corpus that had to be described in code as *the thing that is not a library* would be a code-only synonym for a term the vocabulary is missing.
- [docs/validation.md](../validation.md) records what has been read about the corpus, what the near-duplicate floor was read at, and — the largest of the three — that **nothing has been validated about whether a retrieved phrasing belongs to the family that retrieved it**, which is #64.
- **A new revision of the corpus is a build event, not a copy edit.** Every stored digest fails, the index refuses to build until the record is re-read, and every address written under the old revision still names the old revision — which is why the store is not swept.
