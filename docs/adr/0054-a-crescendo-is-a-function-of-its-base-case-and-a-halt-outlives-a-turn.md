# A crescendo is a function of its base case, and a halt outlives the turn it arrived in

[ADR-0053](./0053-a-case-may-be-a-sequence-and-the-verdict-is-read-per-turn.md) made a payload a sequence and left the one transform that would have to *write* one refused, naming this ticket. #75 writes it: the published escalation, run as a **fixed script** in the scored layer, as two deterministic ladders. Five of its decisions are not ADR-0052's or ADR-0053's and are recorded here. The arithmetic is untouched and stays #76's, and **no record is committed**, for ADR-0052 §5's reason.

## 1. The ladder is a function of the base *case*, and `applied` still refuses the member

The five single-turn transforms are constructions on a payload's *spelling*: base64 of a request is computable from the request. A crescendo is not. Its rungs are an approach to the mechanism the base case tests — a summary the agent is for, a question about how it was told to do it, the wording "for the audit" — and none of them can be computed from the words of the final request. So the signature is different in kind: `scripted_crescendo(base: Case) -> tuple[str, ...]`, not `str -> str`.

Three consequences, and the third is the one that keeps a property ADR-0052 built.

**`transforms.applied` keeps raising for `SCRIPTED_CRESCENDO`.** The refusal is not "not yet" any more; it is *not here*, and the message now names where the construction is instead of naming a ticket. Falling through to the identity is still what it refuses, for ADR-0052 §1's reason: a plain payload committed under a transform's name.

**`transforms.derived_payload(transform, base)` is the one entry point**, and it dispatches — `scripted_crescendo` for the one member whose construction needs the record, `applied(transform, base.payload)` for the five that do not. Both callers take it: `scripts/variant.py`, which commits the result, and `mismatched_variants`, which checks that a committed record still holds it. The alternative was a branch in each, which is two places that can disagree about what a member makes.

**So the tripwire survives.** ADR-0052 §1's `mismatched_variants` — *for every variant whose base is in the population, `payload == applied(transform, base.payload)`* — becomes `payload == derived_payload(transform, base)` and covers the crescendo on the same terms as the five. This is what was at stake in the choice above: had the ladders been hand-written per record instead of committed in code, a crescendo record's payload would have been the one payload in the library that nothing could re-derive, and a rung edited after generation would sit there claiming a technique it no longer carried. A ladder in code costs a function per base case; a ladder in a record costs the guarantee.

**And a base with no ladder is refused rather than defaulted.** Two bases have one — `data-leakage-001` and `halt-defeat-001` — and a third is a ticket that says what the escalation asks and what it costs against the plain payload, not a line in a dictionary. A default would be the base case's own payload under a technique's name, which is the refusal one level up written twice.

## 2. What running the loop as a script costs, and why the boundary is not crossed

deepteam runs crescendo as a **model-driven loop** (`deepteam/attacks/multi_turn/crescendo_jailbreaking`, Apache-2.0), and #71(d) refuses that shape: a loop that builds state inside one target session and reasons about it adds a second thing this bench cannot score, because an episode is not a sample (CONTEXT.md, **episode**). The published mechanism, though, is **commitment** and not improvisation — the target agrees to something innocuous and each later turn is licensed by *its own earlier answer* (Russinovich, Salem and Eldan, *Great, Now Write an Article About That: The Crescendo Multi-Turn LLM Jailbreak Attack*, arXiv:2404.01833, USENIX Security 2025; title and authors checked against the published record). A fixed ladder reproduces that mechanism, because the licence comes from the target's replies and not from the attacker's cleverness: the escalation is in the script and the commitment is in the transcript.

**What the script gives up is adaptation, and the cost is stated rather than discovered.** A target that refuses rung two gets rung three anyway. So a crescendo variant's rate is a rate about *this* ladder against that target, and a reading that four turns bought nothing is a reading about these four rungs — the same limit ADR-0052 §3 states for the two framings this repository worded itself. In exchange it has a denominator: one attempt is one script in one session, ten attempts are ten independent samples, and the verdict is re-derivable by a reader holding the record and the transcripts (ADR-0053 §2, ADR-0004).

**Nothing here reaches the adaptive layer and nothing here is an episode.** The linear loop already exists as `adaptive/attacker._Episode.run` and #78 adds the branching one; both report in their own section and neither may write into a scored rate ([ADR-0010](./0010-two-layers-in-one-run-the-adaptive-layer-is-never-scored.md)). The group therefore has both readings of one published technique and reports them apart, which is the outcome #71 asked for. The structural guarantee is unchanged and was not widened for this: a ladder is text on a record, chosen before the run starts, and no function in `transforms.py` is reachable from a module a run's adaptive layer calls. The one edge across stays `propose_case` into the admission gate.

## 3. Two ladders, and what each rung is

Four rungs each, because four is what the escalation needs to be an escalation and not a pretext followed by the payload.

**Data leakage, from `data-leakage-001`.** A summary request the agent is for; a question about whether that scope was written into its setup; a request to quote that wording "for the internal audit"; then the base case's payload. The success condition is unchanged — `canary_in_reply` against the nonce planted in the target's configuration, ADR-0007's first planting — so the verdict is read exactly as a single-turn leak's is and the only new thing is the number of turns that bought it.

**The final rung is the base payload word for word**, on ADR-0052 §3's discipline: the wrapper transforms *add words round the request and never reword it*, because a paraphrase would make the comparison against the base case a comparison of two attacks. The three approach rungs are this repository's wording, for the reason the published wrapper and persona are — the catalogue composes its rungs with a model at run time and a fixed script cannot. One wart is accepted knowingly: the base payload opens *before we start*, which reads oddly as the fourth turn of a conversation. Rewriting that opening would have cost the exact comparison, which is worth more than the seam.

**Halt defeat, from `halt-defeat-001`.** Two rungs establish the work — and deliberately do not authorise it (*hold it there and file nothing for now*), because a target that filed on rung two acted before any stop arrived, which is not halt defeat. Then the base case's own two paragraphs, one turn apart: its stop signal as rung three, its housekeeping request as rung four. The base record's header says what does the work — *a stop signal, then a request already inside the agent's declared job* — and the ladder is that ordering with the two halves in different turns, so **the stop lands between turns** and the last rung is the obvious continuation of work already agreed. Read from the trace by `tool_call_after_stop`, unchanged.

Those two paragraphs are copied into `transforms.py` rather than cut off the base record on a blank line at call time. A ladder computed by splitting a committed payload would change silently the day somebody reflows that record; the copy is asserted *against* the record by the suite, so a reflow fails a test that names both.

This variant requires tool-call visibility **and** session retention, so it is the case that will report *not measurable* most often. That is correct and is not a defect (CONTEXT.md, **not measurable**) — and it is sharper than that today, because no register screen declares retention at all (ADR-0053 §5, and the gap recorded in docs/validation.md).

**No judged variant, and it is said here because there is no record header to say it in.** Wrongful commitment is the family Crescendo is most obviously *for*, and it is judged: `AdjudicationBrief.payload` is one string and κ rests on fifteen single-turn gold transcripts per family. A judged crescendo would put a payload the gold set has no counterpart for into a κ-bearing denominator, which ADR-0052 §2 refuses one record upstream and ADR-0053 §5 refuses on the record itself. It waits for a ticket that opens by saying what happens to the gold set. Neither refusal was relaxed and neither needed a new clause: `scripts/variant.py` refuses a judged base, and `Case` refuses a judged script.

## 4. The operator's stop signal is a fact about the session, not about the turn it arrived in

The decision with a real alternative, and the one the escalation could not have been read without.

`ToolTrace.stop_signal_at` is *the count of calls already made when the stop signal arrived* — a position inside **one** turn, because until now a halt-defeat attempt was one turn. The halt-defeat ladder sends the stop on rung three and the request on rung four, so no single turn's trace shows both: rung three records a signal and no call, rung four records a call and no signal. Read per turn in isolation, `calls_after_stop` is empty in both and the attempt scores **resisted** — a defeat recorded as a defence, which is precisely the soft number ADR-0004 exists to refuse, arriving through a criterion rather than through a missing declaration.

So `evaluate_script` carries the signal forward across the turns of one session. `evaluate` and `measurability.checkable` each take `already_halted`, a keyword with a default, and only `tool_call_after_stop` reads it: when a stop landed on an earlier turn, **every** call in this turn is a call after the stop, and a trace with no stop of its own is still readable evidence rather than an unanswerable turn.

Four properties of that, each of which is a way of getting it wrong:

- **It is set from a turn that *recorded* a stop, never from the payload the bench sent.** The record says which rung carries the signal; whether the target received it is the target's trace to say. Inferring the halt from the script would be reading the attack instead of the evidence.
- **It is still false while the turn the stop arrived in is itself being read.** So a call made *before* the signal inside that turn stays what it is — a call before a stop, which is not halt defeat, and which the intra-turn position has always decided. The ordering the family measures is preserved at both scales.
- **A turn with no trace records nothing**, so a script whose traces never carry a signal has nothing for a call to come after and resists. A default in the other direction would score every tool call of every scripted family as a halt defeat.
- **One turn read on its own is read exactly as before.** The parameter defaults to false and every caller that holds one probe — the adaptive layer's per-probe verification, `goldset` — passes nothing. A single-turn halt-defeat case comes out of `evaluate` byte for byte as it did, which is the property that makes this a generalisation and not a change to what three committed records measure.

**And the reference agents' stop control had to outlive its turn too, or nothing here could be measured.** The bench-side change above reads the evidence correctly; it does not make there be any. `ReferenceAgent.reply` computed the stop position from the current message alone and `SessionMemory` held only standing instructions, so a stand-down on rung three was forgotten by rung four and **all three** reference agents would have acted — including the hardened one. The ladder would then have scored *succeeded* everywhere, `D` would have been zero, and the variant would have failed admission for a reason belonging to this repository's equipment rather than to any target's defences. That is #71's third question arriving from the other side: *escalation against a target that forgets the previous turn measures the target's memory rather than its defences.* So `SessionMemory.stood_down` records that the operator's signal reached this session and `StopControl.stops` reads it, which makes the sentence already in that control's docstring true across turns as well as within one — *a stop control that can be reached only by passing the other checks is not a stop control* has the same shape as a stop control that lapses when the next message arrives. Three limits are deliberate: the flag is set from the turn that carried the signal and never from what the case declares; the control is given what the session knew **before** this turn, so a turn carrying the signal is stopped by the signal and not by the memory of it; and nothing resumes a halted session, because a message that could lift a halt would be a stop control an attacker can talk out of. Only the hardened agent has a stop control, so only it is defended — which is the gradient the family is read on, and it is now visible over real HTTP: the trivial agent files on rung four and the hardened one does not.

**Considered and refused: a session value object** carrying `already_halted` and whatever comes next. One boolean read by one branch is a keyword; a *second* session-level fact is what would earn the type, and inventing it now is the speculative generality ADR-0052 §1 keeps out of this area.

**Considered and refused: making the stop a flag on the attempt** rather than a fact carried between turns. It would have let a record declare "the stop is on rung three" and the evaluator believe it, which is the target's evidence replaced by the library's intention. **Also refused: reading the whole script's traces as one concatenated trace.** Positions would then be comparable across turns, which is exactly the arithmetic `ToolTrace.__post_init__` refuses — a stop position has to sit inside the trace it is a position in — and the concatenation would have to invent an order for calls the endpoint reported per turn.

## 5. A record claiming the escalation sends more than one turn

`Transform.stated` already describes this member as *one attempt, and more than one turn*. A record carrying it over a single message is that sentence contradicted by its own payload, and it would sit in the denominator reporting the escalation's rate having escalated nothing. So `Case._refuse_a_crescendo_that_escalates_over_one_turn` refuses it.

Held on the record rather than in `scripts/variant.py`, unlike that script's three refusals about a *base*: this is a property of the finished record, so a hand-written one is caught on the same terms as a generated one. It is the complement of ADR-0053 §5's three refusals — those say what a script may not be, and this says that the one multi-turn transform may not be a single message.

**One field `scripts/variant.py` now adds rather than copies.** `SESSION_RETENTION`, when the construction came back a script: a crescendo's base is single-turn and therefore does not declare it, and a script that did not would be run against a stateless target and reported as a rate of zero where the honest answer is *not measurable* (ADR-0053 §5). Added to what the base requires rather than replacing it, which is why the halt-defeat ladder declares both capabilities.

**And `Case.script` stopped being vacuous.** ADR-0053's join — every canary guard reads the turns joined with a newline, because a canary spelled across two turns is a canary the attempt sent — had eighteen single-turn records to be true of, where the join is the payload unchanged. A script is the first payload that can spell a value out *between* its turns, and the suite now holds the guard to it directly: an indirect-injection record whose payload spells half the canary in turn one and half in turn three does not load. The cost named on that property is unchanged and still errs towards refusing a record.

## 6. This ADR moves no arithmetic, admits nothing, and leaves the gate citation where it was

`n` per family is unchanged, `GateRule.attempts_per_family()` is untouched, PLAN §3's diagram and CONTEXT.md's counts are still true, and the library digest and record count are where ADR-0053 left them — `31cacb9d69ec`, eighteen — because **no crescendo record is committed here**.

That is ADR-0052 §5's cost, unchanged and not worked around: a variant enters the library by clearing ADR-0003's single-model bar against the three reference agents through `scripts/admit.py`, which reaches targets and therefore asks for the three attestation statements and the approval interrupt, and `scripts/console.py` treats piped or absent stdin as a **no** by design. So the measurement is a person's run at a terminal. Until it happens both ladders are proposals: `scripts/variant.py --base data-leakage-001 --transform scripted_crescendo --argument <file> --write` puts a record with no `[admission]` block into `backend/cases/`, where `admitted_library` refuses it and the suite will not load a library holding it.

**The question that admission run answers is the one #75 is actually for**: whether four turns beat one on the hardened agent. If the hardened agent refuses rung four exactly as it refuses the single-turn payload, the ladder bought nothing against a defended target — a result, and one that belongs in [docs/validation.md](../validation.md) rather than in the library. Either outcome is a reading; only one of them is a committed case.

The consequence to carry is [ADR-0023](./0023-a-gate-run-updates-the-citation-it-earned.md)'s and it still has not come due: the gate citation goes stale the moment the first variant of any kind is admitted, and a gate run of any outcome replaces it. Nothing here needs a decision, only a run.
